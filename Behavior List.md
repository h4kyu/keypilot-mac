The ideal behavior list should be **action-based**, not shortcut-based. The app should notice repeated mouse/menu/trackpad behavior and teach the keyboard path for that specific behavior.

## Priority 1: Core universal behaviors

These should be coached first because they are common, high-confidence, and easy to explain.

|Observed behavior|Coach shortcut|
|---|---|
|Uses menu or context menu to Copy|`⌘C`|
|Uses menu or context menu to Paste|`⌘V`|
|Uses menu or context menu to Cut|`⌘X`|
|Uses menu to Undo|`⌘Z`|
|Uses menu to Redo|`⌘⇧Z`|
|Uses menu to Select All|`⌘A`|
|Uses menu to Save|`⌘S`|
|Uses menu to Find/Search|`⌘F`|
|Clicks red close button|`⌘W`|
|Uses File → New / New Window / New Document|`⌘N`|
|Uses File → Open|`⌘O`|
|Uses File → Print|`⌘P`|
|Uses app menu → Preferences/Settings|`⌘,`|
|Uses menu to Quit app|`⌘Q`|
|Uses menu to Hide app|`⌘H`|
|Uses menu to Minimize window|`⌘M`|

## Priority 4: Text editing and cursor movement

This is where the product can become genuinely useful, but hints need restraint.

|Observed behavior|Coach shortcut|
|---|---|
|Drags to select a word repeatedly|Double-click|
|Drags to select a paragraph repeatedly|Triple-click, where applicable|
|Uses mouse to move cursor to line start|`⌘←`|
|Uses mouse to move cursor to line end|`⌘→`|
|Uses mouse to move cursor by word|`⌥←` / `⌥→`|
|Deletes characters one by one|`⌥Delete` for word delete|
|Selects text manually then deletes|`⇧` + arrow selection patterns|
|Uses menu to paste and match style|`⌘⌥⇧V` where available|
|Uses menu to check spelling|app-specific|
|Opens emoji picker from menu|`⌃⌘Space`|
|Uses formatting menu for bold|`⌘B`|
|Uses formatting menu for italic|`⌘I`|
|Uses formatting menu for underline|`⌘U`|

Be careful here: cursor-movement hints can feel intrusive. Only show after repeated behavior.

## Priority 9: Power-user shortcuts, opt-in only

These are valuable but should not be default for family/non-technical users.

|Observed behavior|Coach shortcut|
|---|---|
|Manually arranges windows|tiling/window shortcuts if available|
|Uses terminal copy/paste incorrectly|terminal-specific shortcuts|

|Repeats multi-step workflows|suggest custom shortcut or automation later|

## Behaviors to avoid coaching at first

Do **not** coach these in MVP:

|Behavior|Reason|
|---|---|
|Password entry|Sensitive context|
|Banking/medical/private apps|Trust risk|
|Arbitrary web-app buttons|Too brittle|
|Complex drag-and-drop|Ambiguous|
|Drawing/design gestures|Mouse may be optimal|
|Gaming|Wrong context|
|Video editing timelines|Mouse may be intentional|
|Remote desktop sessions|You are observing the local client, not the remote OS|
|Screen sharing/presentations|Overlay may be embarrassing or disruptive|
|One-off actions|Not enough evidence|
|Actions with no clear shortcut|Avoid noisy hints|

## Ideal coaching taxonomy

The internal product taxonomy should look like this:

```text
Action Detectors
├── MenuCommandDetector
│   ├── App menu items
│   └── Context menu items
├── WindowControlDetector
│   ├── Close
│   ├── Minimize
│   └── Window switching
├── BrowserChromeDetector
│   ├── Address bar
│   ├── New tab
│   ├── Close tab
│   ├── Tab switching
│   ├── Back/forward
│   └── Reload
├── DockAndAppSwitchDetector
│   ├── Dock app switching
│   └── App activation patterns
├── FinderDetector
│   ├── File operations
│   ├── Rename
│   ├── Trash
│   └── View/navigation
├── TextEditingDetector
│   ├── Selection
│   ├── Cursor movement
│   ├── Formatting
│   └── Deletion
└── KeyboardShortcutDetector
    ├── Detect learned shortcuts
    └── Retire hints after adoption
```

## The ideal first shipped list

For a strong v1, ship these 15:

```text
1. Copy → ⌘C
2. Paste → ⌘V
3. Cut → ⌘X
4. Undo → ⌘Z
5. Redo → ⌘⇧Z
6. Select All → ⌘A
7. Save → ⌘S
8. Find → ⌘F
9. Close Window/Tab → ⌘W
10. New Window/Document → ⌘N
11. New Browser Tab → ⌘T
12. Browser Address Bar → ⌘L
13. Browser Back → ⌘[
14. Browser Forward → ⌘]
15. Switch Apps via Dock → ⌘Tab
```

That is the right starting point: common, understandable, useful, and broad enough to feel like a desktop coach rather than a menu-item toy.
